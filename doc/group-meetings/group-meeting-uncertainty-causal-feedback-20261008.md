## 1. 我们当前做到了什么，问题在哪里？

| 项目 | 已有结果 | 说明 |
|---|---:|---|
| 检测 Macro-F1 | **74.76%** | 651 例权威结果，非单独的 Recall 或 Accuracy |
| 检测 Precision | **89.54%** | 仍有漏检：权威统计 127 FN |
| 错误步骤精确命中 | **27.21%（114/419）** | 分母为全部金标幻觉案例，含漏检 |
| 步骤晚判 | **172/292（58.9%）** | 终局已检出案例；模型容易指向错误被使用/交付的后续步骤 |
| 自进化 | **3 轮，0 准入** | 7 个开发版本，4 个局部冻结，3 个正式不可测、1 个拒绝 |

**矛盾：能检出一部分错误，但经常找不准“最早错在哪一步”；定位诊断也没有充分反馈到漏检复核和后续进化。**

## 2. 核心想法：快慢结合、双向反馈

`Task + Agent 长轨迹` → **快层：逐步疑惑度/风险分数** → 选择 Top-K 可疑步骤及前因 → **慢层：真实后续依赖追踪 + 有限反事实审查** → 输出带证据的根因候选。

- **初判有幻觉**：让 Step Tracer 不只盯着最终错误结果，而是沿因果链寻找**首次引入错误**的一步；原 Defense 保留。
- **初判无幻觉**：如果定位审计发现**有证据的具体偏差**，触发原有 Recall → Causal Upgrade → Defense，复核 Judge 可能漏掉的错误。
- **定位和检测结果**：仍由原有 Adjudication 统一裁决。**高困惑度 ≠ 幻觉证据，不能直接改判。**
- **自进化**：把“哪一步、为何传播、哪个候选修复、伤了哪些正常邻居”反馈给现有 Worksheet/Proposer/Gates，形成可验证的修复建议。

## 3. 一个容易理解的例子

工具第 2 步返回“2024 年收入 **100**”，Agent 第 3 步误记为 **80**，第 4 步据 120 和 80 算出“增长 **50%**”，第 5 步最终交付 50%。

传统定位可能指向计算/交付（第 4/5 步）；我们希望依据**来源证据、值传播和最小修正**定位第 3 步。若修正为 100，算式为增长 20%。这是假设案例，用于展示机制，不代表真实 benchmark 命中。

## 4. 我们和已有方法的区别

**不是只给长轨迹多问几次大模型**：

1. **可审计的快筛**：逐步风险分数定位候选，避免每步都做昂贵推理；同时检查 Top-K 是否覆盖真实根因。
2. **因果慢审**：把首次错误、后续传播、最终交付、已经修复的中间错误分开。
3. **双向检测反馈**：定位不再是判完后的一次性附属输出，而是能用**可核查证据**重新触发漏检复审。
4. **机制级自进化**：不是一句“上次失败了”，而是记录具体可改的错误机制和正常反例。

注意：真实 PPL 需要支持对历史动作计算 token 条件似然的评分后端；当前 Chat Completions 代码无此能力。首版建议先用**结构化语义风险代理**，之后再与真实 PPL 比较。

## 5. 怎么接进现有代码？

## 6. 实验如何证明有效？

固定底座、预算、数据角色与外部证据来源，比较：

- **G0 原系统** vs **等成本逐步复审** vs **风险快筛** vs **快筛+后续依赖** vs **快筛+依赖+有限推演**。
- 在前述最优冻结方案上，**单独开启阴性 Recall 反馈**，检验 FN 是否下降、FP 是否上升。
- 再单独比较**普通反馈**与**结构化因果反馈的自进化**。

主要看：**所有金标阳性的精确步骤命中、候选 Recall@K、Macro-F1、FN/FP、Token/时延、是否真实准入且不伤正常案例**。已有 693 例历史均暴露，内部对照不能当作外部泛化，最终需新案例。

## 7. 下一阶段与组会希望确认的三件事

**第一步**：修正基线偏移统计；离线完成疑惑度风险画像和因果链旁路审计（不改现有判决）。
