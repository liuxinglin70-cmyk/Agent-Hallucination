## 2. 旧样本五次运行：机制没有复现增益

旧样本上，机制开启后的三次运行（#3、#4、#5）相对各自的基线：

- **#3 next_action100**：检测 76→76、定位 27→27、FP 4→4，配对 4 修正 / 4 回退、2 修正 / 2 回退，净增益 0。
- **#4 mechanism 第一轮**：相对 #3 同 99 例，检测 2 修正 / 5 回退、定位 1 修正 / 3 回退（75→73、26→25、FP 4→6），净负。
- **#5 mechanism 优化复测**：预注册基线是 recent_off，检测 3 修正 / 6 回退、定位 3 修正 / 5 回退；相对 #3 为检测 2 修正 / 5 回退、定位 2 修正 / 4 回退；相对 #4 为检测 2 修正 / 3 回退、定位 2 修正 / 3 回退。仍未形成净收益。

共同特征：**模型预测只覆盖 43/26/26 例（#3/#4/#5）**，实际使用 47/42/43 例，其余使用来自零请求的确定性边界。定位始终停在基线附近（24–27/61–62）。

旧样本按族看更清楚（基线 → #3 → #4 → #5，定位命中）：

## 3. 新样本与前三次的差异

新样本两轮（#7、#8）与前三次的差别不只是样本，还有实现与预算：

| 维度 | 旧样本三次 | 新样本两轮 |
| --- | --- | --- |
| 预测目标 | 取 Top-K 事件之后的那一步（常是无关的早期步骤） | 取风险事件本身（前缀截止到 t-1），并区分动作检查与响应检查 |
| 每例预测次数 | 1–2（第二次预留给比较修复） | 2（比较修复改为每例一次，第二请求用于第二个风险目标） |
| 新增工作额度 | 180 秒（含批次排队） | 900 秒（含批次排队） |
| 单次预测输出上限 | 4096（未显式设置时） | 8192 |
| 多轮记录 | 有 25 例 BFCL，其中 23 例轮次无法对齐（task_alignment_unknown） | 事前排除，样本全为单任务轮次 |
| 模型预测覆盖 | 43 / 26 / 26（#3/#4/#5） | 81 / 85（#7/#8） |
| 预测实际使用 | 42–47 | 82–86 |
| 额度耗尽 | 15–23 例 | 16 / 13 例（#7/#8） |

结果：旧样本定位停在 24–27；新样本从 18 升到 34 → 36（配对 19 修正 / 1 回退）。

需要如实说明的归因边界：

1. **目标选择修正是主因。** 旧规则在实际运行中只把 11/62 的预测源事件对准金标步、5/62 对准金标步的下一事件；在旧 100 例上离线重放旧规则为 16/62 与 8/62。同一批案例重放新规则，目标命中金标步为 20/62（cap=1）、31/62（cap=2）、37/62（cap=3）。旧样本之所以没有提升，不是“样本太难”，而是预测打偏了。
2. **覆盖提升一半来自预算，一半来自范围。** 180 秒额度在高并发下因排队耗尽，旧样本 15–23 例 `budget_exhausted`（#3 为 23、#4 为 15、#5 为 17）；新样本 900 秒后为 16 / 13 例。同时排除多轮 BFCL 后，23 例 `task_alignment_unknown` 消失。两者叠加把模型预测覆盖从 26 拉到 81–85（#3 自身为 43）。
3. **旧样本的基线本身偏高。** 旧样本反复用于开发（10-15 至 10-17），基线定位 27/62 = 43.5%；新样本基线 18/62 = 29.0%。新样本的定位提升有更大空间，但也有更强的“未见数据”证据。
4. **跨样本检测数不可比。** 新样本基线检测 82/100 高于旧样本基线的 68–76/100，说明新样本对检测更容易；因此不能说“本轮 82 比上一轮 76 更好”。

## 6. 结论

- **机制在旧样本上没有复现增益**：三次运行检测与定位均未超过各自基线。
- **修复后在新样本上复现了定位增益**：18/62 → 36/62，配对 19 修正 / 1 回退，检测与基线持平。
- **但五次运行没有一次通过各自预注册的验收标准**；最新一轮只差 FP 一项（7 对 6）。
- 增益不能全部归因于单模块：新样本对照是归档 G0 基线，源码与预算不同；也未做同源码 off/on 配对消融。
- 新样本的定位基线更低、检测基线更高，说明两套样本难度不同；跨样本数字只能看方向。
