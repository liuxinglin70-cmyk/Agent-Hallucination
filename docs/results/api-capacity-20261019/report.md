# DeepSeek API 容量测试（2026-10-19）

默认模型与 judge/defense/recall 路由已切换为 `DeepSeek-V4.1-Flash-1017`；AutoDL 返回模型 `deepseek-v4-1-flash-261017`。直连 DeepSeek 备用配置不变。三个实际 provider 路由 JSON 冒烟通过，配置离线测试 71 项通过。

## 建议

日常全局 API 在途并发先用 **64**；本次合成负载实测最高全通过档位为 **128**。256 并发 HTTP 均成功，但 768 次中有 3 次输出内容错误，不能视为业务稳定通过。尚未测得供应商硬并发、RPM 或 TPM 上限。64 是留余量的工程建议，并非已验证的业务最优值。

批处理使用 `--workers 64 --provider-concurrency 64`；需要尝试实测高档位时，两者均设 128。单独增加 provider-concurrency 而保留默认 8 个 case workers，通常不能填满请求并发。没有自动修改全局调度默认值或启动真实数据集测量。

## 测量边界

阶梯测试共 3052 次请求，响应 usage 累计 15,114,954 tokens（包含思考 tokens、重复输入和缓存计量；不是账单金额）；另有首次连通性 1 次和实际 provider 冒烟 3 次。所有测试无自动重试。没有 429、HTTP 失败或限额响应头。

短提示要求 JSON {"ok":true}。128-token 输出预算在 8 并发时有 1 次思考耗尽预算、finish_reason=length；提高至 1024 后复测。256 并发的 3 个错误均 HTTP 200、finish_reason=stop，但 ok 字段不是 true；不能从这组观测证明错误由并发导致，也不能用 HTTP 200 代替有效成功。

长提示每次平均约 8,084 输入 tokens，返回 0..127 的整数 JSON 数组，平均约 400 输出 tokens，输出上限 4096。固定上下文可能命中缓存，不代表全新长上下文的处理容量；这不是检测器真实大轨迹、复杂合同或长输出效果验收。

128 并发长提示重复测试 10 轮、1280/1280，通过 81.91 秒，15.63 有效请求/秒，约 938 次/分钟等效平均。此为按轮突发、等待每轮全部完成后继续的吞吐；不是持续饱和流量，也不是已确认的 RPM 配额。用户随后要求不要10轮，该组在消息到达前已完成，不再重复或继续加压。

并发指客户端同步放行的线程数，包含建连、发送和等待，不能证明服务端同时推理数量。延迟为含建连的完整响应时间；未测首 token 延迟或单请求生成 tokens/秒。实测最高全通过档位128是有限样本观测，不能保证之后零失败。

## 复现

`python scripts/probe_api_capacity.py --levels 16,32,64,128 --rounds 2 --max-tokens 1024 --output <新证据路径>`

长提示另加 `--words 2000 --items 128 --max-tokens 4096`。运行会调用付费真实服务；工具默认2轮，不使用10轮。
